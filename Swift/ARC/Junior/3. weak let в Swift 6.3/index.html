weak let в Swift 6.3

Почему weak раньше нельзя было объявить через let, что изменилось в Swift 6.3, зачем weak let нужен Sendable-классу с делегатом и что SE-0481 меняет для [weak self].

#swift#arc#concurrency#sendable

На собеседовании спрашивают, почему слабую ссылку нельзя объявить через let. Раньше в статье про ARC мы отвечали, что ARC присваивает слабой ссылке nil, когда объект уничтожают, а константу менять нельзя. Ошибка компилятора Swift 6.2.0 объясняла запрет так же. В Swift 6.3 weak let разрешён: переприсвоить такую ссылку нельзя, а после уничтожения объекта её чтение возвращает nil, как и у weak var. Раздел в статье про ARC мы исправили.

!

Нужно знать, что такое слабая ссылка и протокол Sendable. Перед чтением полезно освежить 2. Подробнее про ARC и 4. Sendable.

Пример

Загрузчик картинок сообщает экрану профиля, что аватар готов. Экран он держит слабой ссылкой, чтобы не продлевать ему жизнь. Делегат задаётся один раз в init и дальше не меняется, поэтому он объявлен через let:

SWIFTImageDownloader.swift
protocol ImageDownloaderDelegate: AnyObject {
    func downloaderDidFinish()
}


final class ImageDownloader {
    weak let delegate: (any ImageDownloaderDelegate)?


    init(delegate: any ImageDownloaderDelegate) {
        self.delegate = delegate
    }


    func finish() {
        delegate?.downloaderDidFinish()
    }
}


final class ProfileScreen: ImageDownloaderDelegate {
    func downloaderDidFinish() { print("Аватар загружен") }
    deinit { print("ProfileScreen уничтожен") }
}


var screen: ProfileScreen? = ProfileScreen()
let downloader = ImageDownloader(delegate: screen!)
downloader.finish()                 // Выведет: Аватар загружен
screen = nil                        // Выведет: ProfileScreen уничтожен
print(downloader.delegate == nil)   // Выведет: true
downloader.finish()                 // ничего не выведет

Что отвечает компилятор

Компилятор Swift 6.2.0 на строке с weak let выдавал ошибку:

TEXT
error: 'weak' must be a mutable variable, because it may change at runtime

В Swift 6.3.1 из Xcode 26.4.1 пример собирается без флагов и выводит три строки из комментариев. Режим Swift 5 или Swift 6 здесь ничего не меняет. Не меняет и настройка Default Actor Isolation в Build Settings цели. По умолчанию она равна nonisolated, а шаблон нового приложения ставит её в MainActor.

СлучайSwift 6.2.01Swift 6.3.1, nonisolatedSwift 6.3.1, MainActor
объявление weak let delegateошибкасобираетсясобирается
чтение после уничтожения экранаошибка на объявленииnilnil
delegate = nil после initошибка на объявленииошибкаошибка
weak let без ?ошибкаошибкаошибка

Запрет снял proposal SE-0481. Он объясняет, почему слабой ссылке подходит let: screen = nil не меняет downloader.delegate. В свойстве лежит та же ссылка, но экрана уже нет, поэтому чтение возвращает nil.

let запрещает только вашему коду присвоить новое значение после init. Метод, который сбрасывает делегата, с weak let не соберётся:

SWIFT
func cancel() {
    delegate = nil
}
TEXT
error: cannot assign to property: 'delegate' is a 'let' constant
note: change 'let' to 'var' to make it mutable

Если делегата нужно менять или сбрасывать после init, оставьте weak var. Опциональный тип обязателен и для weak let. На weak let delegate: ProfileScreen Swift 6.3.1 отвечает error: 'weak' variable should have optional type 'ProfileScreen?'.

Sendable-класс с делегатом

Загрузчик, который передают между задачами, помечают Sendable. Класс, не привязанный к актору, SE-0302 разрешает помечать Sendable, только если он final, а все его хранимые свойства неизменяемы и сами Sendable. Свойство weak var под это правило не подходит:

SWIFTImageDownloader.swift
protocol ImageDownloaderDelegate: AnyObject, Sendable {
    func downloaderDidFinish()
}


final class ImageDownloader: Sendable {
    weak var delegate: (any ImageDownloaderDelegate)?


    init(delegate: any ImageDownloaderDelegate) {
        self.delegate = delegate
    }


    func finish() {
        delegate?.downloaderDidFinish()
    }
}

В режиме Swift 6:

TEXT
error: stored property 'delegate' of 'Sendable'-conforming class 'ImageDownloader' is mutable

В режиме Swift 5 это же сообщение приходит предупреждением с припиской this is an error in the Swift 6 language mode. Замените var на let в шестой строке, и сообщение пропадёт в обоих режимах, а программа из примера снова выведет Аватар загружен.

final class ImageDownloader: SendableSwift 5, nonisolatedSwift 6, nonisolatedSwift 5 и 6, MainActor
weak var delegate, протокол Sendableпредупреждениеошибка is mutableсобирается
weak let delegate, протокол Sendableсобираетсясобираетсясобирается
weak let delegate, протокол без Sendableпредупреждениеошибка contains non-Sendable typeсобирается

weak let сам по себе класс Sendable не делает. Тип делегата тоже должен быть Sendable, поэтому у протокола стоит AnyObject, Sendable.

С настройкой MainActor ошибок нет, потому что класс без явной изоляции тогда становится @MainActor. Такой класс считается Sendable и с изменяемыми свойствами, ведь обращаться к ним можно только через главный актор. Чтобы повторить ошибки из таблицы в новом приложении, поставьте в цели Default Actor Isolation = nonisolated.

Слабые ссылки в @Sendable-замыканиях

Пусть загрузчик из прошлого раздела, уже с weak let delegate, запускает работу в фоновой очереди. DispatchQueue.global().async принимает @Sendable-замыкание, и загрузчик захватывает в нём себя слабой ссылкой, чтобы очередь не продлевала ему жизнь:

SWIFT
func start() {
    DispatchQueue.global().async { [weak self] in
        self?.finish()
    }
}

Вызов downloader.start() выводит Аватар загружен в режимах Swift 5 и Swift 6.

SE-0481 делает слабый захват константой, как любой другой захват из списка. В Swift 6.3.1 это правило включает флаг ImmutableWeakCaptures. По умолчанию он выключен и сам включится только в одном из будущих режимов языка. Отдельной настройки для него в Xcode 26.4.1 нет: флаг добавляют строкой -enable-upcoming-feature ImmutableWeakCaptures в Other Swift Flags, а в пакете SwiftPM пишут .enableUpcomingFeature("ImmutableWeakCaptures") в swiftSettings цели.

Замыкание в start()Без флагаС флагом ImmutableWeakCaptures
self?.finish()собираетсясобирается
self?.finish() и self = nilсобираетсяошибка immutable capture

Режим Swift 5 или Swift 6 на результат не влияет. На self = nil с флагом компилятор отвечает error: cannot assign to value: 'self' is an immutable capture. В SE-0481 для чтения из слабого захвата в @Sendable-замыкании показана ошибка reference to captured var, но Swift 6.3.1 её не выдаёт ни в одном режиме, поэтому флаг в нашем примере меняет только присваивание.

С Default Actor Isolation = MainActor режим Swift 6 добавляет предупреждение call to main actor-isolated instance method 'finish()' in a synchronous nonisolated context. Метод finish() тогда привязан к главному актору, а замыкание выполняется в фоновой очереди.

Как узнать о таком изменении самому

Старый ответ встречается не только у нас. Даже книга The Swift Programming Language (версия для Swift 6.4) пишет, что слабые ссылки «always declared as variables», и так же отвечают списки вопросов к собеседованию. Где искать актуальное правило:

  1. Шапка proposal. Строка Status: Implemented (Swift 6.3) называет версию, а Upcoming Feature Flag: ImmutableWeakCaptures показывает, что часть изменения пока включается флагом. Proposal ищут на странице Swift Evolution или в репозитории swiftlang/swift-evolution.
  2. CHANGELOG.md в репозитории swiftlang/swift на теге вашей версии. О SE-0481 в нём записи нет, поэтому одного CHANGELOG мало.
  3. Компилятор вашей версии. xcrun swiftc --version покажет версию, а файл из трёх строк с weak let, собранный в вашем проекте, покажет правило. Для правил про Sendable важны и настройки цели: режим языка и Default Actor Isolation.

Вопрос к ассистенту

Ассистент знает язык по материалам до определённой даты, а Swift 6.3 вышел в марте 2026 года. Добавьте к вопросу строку с версией компилятора и попросите ссылку на proposal:

TEXT
Компилятор: Apple Swift version 6.3.1, Xcode 26.4.1, режим Swift 6. Можно ли объявить weak через let? Дай ссылку на proposal и его статус.

По ссылке прочитайте шапку proposal, а код из ответа соберите в своём проекте. Этот порядок работы подробно разобран в статье про изучение iOS с ассистентом.

Вопросы на собеседовании

Прежде чем раскрыть ответ, сформулируйте свой.

?Можно ли объявить слабую ссылку через let?›

Можно, начиная со Swift 6.3. Раньше компилятор требовал var, потому что считалось, что при уничтожении объекта ARC перезаписывает ссылку на nil. По SE-0481 ссылка остаётся той же, просто её чтение после уничтожения объекта даёт nil. Переприсвоить weak let нельзя, тип должен быть опциональным, а пригодится он прежде всего Sendable-классам.

?Зачем weak let, если есть weak var?›

Для классов, которые передают между задачами. Класс, не привязанный к актору, SE-0302 разрешает помечать Sendable, только если все его хранимые свойства неизменяемы. Поэтому в режиме Swift 6 загрузчик из статьи собирается с weak let delegate, а с weak var delegate даёт ошибку is mutable.

?Что будет выведено?›
SWIFT
final class ProfileScreen {
    deinit { print("ProfileScreen уничтожен") }
}


struct AvatarRequest {
    weak let screen: ProfileScreen?
}


var screen: ProfileScreen? = ProfileScreen()
let request = AvatarRequest(screen: screen)
print(request.screen == nil)
screen = nil
print(request.screen == nil)
TEXT
false
ProfileScreen уничтожен
true

request объявлен через let, его поле тоже let, и всё же после уничтожения экрана чтение поля даёт nil.

?Вызовется ли didSet у weak var, когда объект уничтожат?›
SWIFT
final class ProfileScreen {}


final class ImageDownloader {
    weak var delegate: ProfileScreen? {
        didSet { print("didSet") }
    }
}


var screen: ProfileScreen? = ProfileScreen()
let downloader = ImageDownloader()
downloader.delegate = screen
screen = nil
print(downloader.delegate as Any)
TEXT
didSet
nil

didSet срабатывает один раз, на явном присваивании. Когда экран уничтожен, наблюдатель молчит, хотя чтение уже даёт nil. Решение о принятии SE-0481 называет это поведение согласованным с новым объяснением, в котором сама слабая ссылка не меняется.

Итог

  • weak let разрешён с Swift 6.3 (SE-0481) в свойствах классов и структур и в локальных константах, в режимах Swift 5 и Swift 6, без флагов. Swift 6.2.0 отвечал на него ошибкой 'weak' must be a mutable variable.
  • Чтение weak let после уничтожения объекта возвращает nil, как у weak var. Переприсвоить её нельзя, тип остаётся опциональным.
  • В Sendable-классе, не привязанном к актору, слабого делегата объявляют через weak let, и тип делегата тоже должен быть Sendable. weak var в таком классе даёт в режиме Swift 6 ошибку is mutable. При Default Actor Isolation = MainActor класс привязан к главному актору, и этих ошибок нет.
  • [weak self], который только читает self, в @Sendable-замыкании собирается в обоих режимах, с флагом и без него. Флаг ImmutableWeakCaptures делает такой захват константой, и в нашем примере с ним перестаёт собираться только присваивание захвату.
  • Версию изменения называет статус в шапке proposal, а действует ли правило у вас, показывает файл с weak let, собранный вашим компилятором. В CHANGELOG записи о weak let нет, книга The Swift Programming Language пока повторяет старое правило.

Практика

Первые две задачи решайте сами, третью вместе с ассистентом.

1. Какие строки не соберутся в Swift 6.3.1 и как их исправить, если cancel должен сбрасывать экран?

SWIFT
final class ProfileScreen {}


struct AvatarRequest {
    weak let screen: ProfileScreen?
    weak let owner: ProfileScreen
}


func cancel(_ request: inout AvatarRequest) {
    request.screen = nil
}
✓Решение›

Две строки, в обоих режимах:

TEXT
error: 'weak' variable should have optional type 'ProfileScreen?'
error: cannot assign to property: 'screen' is a 'let' constant

Первая ошибка относится к owner, потому что слабая ссылка, в том числе weak let, бывает только опциональной. Вторая относится к присваиванию в cancel. Свойство screen меняется после создания, поэтому ему нужен weak var.

SWIFT
struct AvatarRequest {
    weak var screen: ProfileScreen?
    weak let owner: ProfileScreen?
}

2. Загрузчик аватара на сервер передают между задачами, поэтому он помечен Sendable. В режиме Swift 6 при Default Actor Isolation = nonisolated этот код не собирается. Исправьте его так, чтобы загрузчик остался Sendable, а ссылка на делегата осталась слабой.

SWIFT
protocol AvatarUploaderDelegate: AnyObject {
    func uploaderDidFinish()
}


final class AvatarUploader: Sendable {
    weak var delegate: (any AvatarUploaderDelegate)?


    init(delegate: any AvatarUploaderDelegate) {
        self.delegate = delegate
    }
}
✓Решение›

Сначала компилятор показывает одну ошибку:

TEXT
error: stored property 'delegate' of 'Sendable'-conforming class 'AvatarUploader' is mutable

После замены weak var на weak let появляется следующая:

TEXT
error: stored property 'delegate' of 'Sendable'-conforming class 'AvatarUploader' contains non-Sendable type 'any AvatarUploaderDelegate'

Её убирает Sendable в протоколе делегата. В режиме Swift 5 обе ошибки приходят предупреждениями, а при Default Actor Isolation = MainActor их нет совсем.

SWIFT
protocol AvatarUploaderDelegate: AnyObject, Sendable {
    func uploaderDidFinish()
}


final class AvatarUploader: Sendable {
    weak let delegate: (any AvatarUploaderDelegate)?


    init(delegate: any AvatarUploaderDelegate) {
        self.delegate = delegate
    }
}

3. Спросите ассистента «Можно ли объявить weak через let?», добавив строку с версией из раздела Вопрос к ассистенту. Откройте proposal по ссылке из ответа и найдите в шапке статус и флаг. Затем соберите ImageDownloader из раздела Пример в режимах Swift 5 и Swift 6 и добавьте в него метод, который присваивает delegate = nil.

✓Что должно получиться›

В шапке SE-0481 стоят статус «Implemented (Swift 6.3)» и флаг ImmutableWeakCaptures. В Xcode 26.4.1 weak let delegate: (any ImageDownloaderDelegate)? собирается в обоих режимах, а метод с delegate = nil даёт cannot assign to property: 'delegate' is a 'let' constant.

Источники

  • SE-0481 weak let: статус «Implemented (Swift 6.3)», флаг ImmutableWeakCaptures, прежнее и новое объяснение слабой ссылки, пример слабого захвата в @Sendable-замыкании.
  • Решение по SE-0481 на форуме Swift: ссылка остаётся той же, меняется результат её чтения; наблюдатели willSet/didSet.
  • SE-0302 Sendable and @Sendable closures: правило для Sendable-классов.
  • SE-0316 Global actors: тип, привязанный к глобальному актору, неявно считается Sendable.
  • SE-0466 Control default actor isolation inference: с изоляцией MainActor по умолчанию объявления модуля становятся @MainActor.
  • Исходники компилятора Swift:
    • DiagnosticsSema.def на теге swift-6.2-RELEASE, строки 6283-6285: старая ошибка 'weak' must be a mutable variable.
    • TypeCheckAttr.cpp на теге swift-6.2-RELEASE, строки 5248-5252: проверка, которая выдавала эту ошибку. На теге swift-6.2.3-RELEASE её уже нет, а тест weak_ref_sendability.swift собирает weak let.
    • Features.def на теге swift-6.3.1-RELEASE, строка 306: флаг ImmutableWeakCaptures и режим языка, в котором он включится сам.
    • Expr.cpp на теге swift-6.3.1-RELEASE, строки 1373-1375: без флага слабый захват создаётся как var.
  • CHANGELOG.md на тегах swift-6.3.1-RELEASE и swift-6.4.0-RELEASE: записи о SE-0481 нет.
  • The Swift Programming Language, Automatic Reference Counting на теге swift-6.4-fcs: прежняя фраза о том, что слабые ссылки объявляют переменными, и заметка о наблюдателях свойств.
  • Swift.org, Swift 6.3 Released (24 марта 2026 года).
